# Testing Guide

This document describes how to run the unit tests and generate coverage reports for the Calculator Server.

## Test Structure

Tests are organized by layer following the hexagonal architecture:

```
server/
├── core/
│   └── app/
│       └── calculator_test.go      # Business logic tests
├── controller/
│   ├── calculator_test.go          # HTTP handler tests
│   ├── bind_test.go                # Request binding tests
│   ├── response_test.go            # Response handler tests
│   └── router_test.go              # Router tests
├── builder/
│   └── server_test.go              # Server builder tests
├── models/
│   └── calculator_test.go          # Model tests
└── run_tests.sh                    # Test runner script
```

## Running Tests

### Run all tests

```bash
cd server
go test ./...
```

### Run tests with verbose output

```bash
go test -v ./...
```

### Run tests for a specific package

```bash
# Core business logic
go test ./core/app/...

# Controllers
go test ./controller/...

# Builder
go test ./builder/...

# Models
go test ./models/...
```

### Run a specific test

```bash
go test ./core/app -run TestCalculatorApp_Add
```

## Coverage Reports

### Generate coverage report

Using the provided script:

```bash
cd server
chmod +x run_tests.sh
./run_tests.sh
```

Or manually:

```bash
# Run tests with coverage
go test ./... -coverprofile=coverage.out

# View coverage in terminal
go tool cover -func=coverage.out

# Generate HTML report
go tool cover -html=coverage.out -o coverage.html
```

### Coverage Targets

- **Target Coverage**: 95% or higher
- **Coverage Report**: `coverage_report.txt` (generated by script)
- **HTML Report**: `coverage.html` (visual coverage report)

## Test Categories

### Unit Tests by Layer

1. **Core/App Layer** (`core/app/calculator_test.go`)
   - Tests for all calculator operations (Add, Subtract, Multiply, Divide, Negate, Percentage)
   - Error handling tests (division by zero, overflow)
   - Edge cases (zero values, negative numbers, decimal values)

2. **Controller Layer** (`controller/`)
   - `calculator_test.go`: HTTP handler tests with mocked app layer
   - `bind_test.go`: Request validation and binding tests
   - `response_test.go`: Response formatting and error handling tests
   - `router_test.go`: Route registration and integration tests

3. **Builder Layer** (`builder/server_test.go`)
   - Server construction tests
   - CORS middleware tests
   - End-to-end integration tests

4. **Models Layer** (`models/calculator_test.go`)
   - Struct field validation
   - JSON marshaling/unmarshaling tests

## Dependencies

Tests use the following testing libraries:

- `testing` - Go's built-in testing package
- `github.com/stretchr/testify` - Assertion library and mocking
- `github.com/gin-gonic/gin` - HTTP framework (for controller tests)

Install dependencies:

```bash
go mod tidy
```

## Continuous Integration

To integrate with CI/CD pipelines:

```bash
# Run tests
go test ./...

# Check coverage threshold (adjust threshold as needed)
go test ./... -coverprofile=coverage.out
go tool cover -func=coverage.out | grep "total:" | awk '{print $3}' | sed 's/%//' | awk '{if ($1 < 95.0) exit 1}'
```

## Mocking Strategy

The controller tests use testify's `mock.Mock` to create a mock implementation of the `CalculatorApp` interface. This allows:

- Isolation of controller tests from business logic
- Controlled error injection for error path testing
- Verification of method calls and parameters

Example mock usage:

```go
mockApp := new(MockCalculatorApp)
mockApp.On("Add", 5.0, 3.0).Return(8.0, nil)
```

## Best Practices

1. **Test Naming**: Use descriptive names like `TestFunctionName_Scenario`
2. **Table-Driven Tests**: Use for testing multiple scenarios
3. **Mock Isolation**: Always reset mocks between test runs
4. **Error Cases**: Always test both success and error paths
5. **Edge Cases**: Include tests for boundary conditions

## Troubleshooting

### Tests fail with "undefined: assert"

Make sure testify is installed:
```bash
go get github.com/stretchr/testify
```

### Coverage report not generated

Check that tests pass first:
```bash
go test ./...
```

Then generate coverage:
```bash
go test ./... -coverprofile=coverage.out
```
